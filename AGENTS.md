# Information Logistics site rules

For every change to site copy, design, HTML, CSS, JavaScript, assets, metadata, SEO/AEO, accessibility, structured data, robots directives, sitemap entries, or deployment:

1. Read and follow `.codex/skills/infolog-site-audit/SKILL.md` before editing.
2. Use `locomotive-preview-b-signal-chamber/` as the production source in the design workspace. In the `infolog-io/informationlog.github.io` GitHub Pages checkout, use the repository root. Never substitute another preview.
3. Write in the Information Logistics “we” voice. Never add one-person, one-man, solo, principal-led, staffing-size, or staffed-studio language.
4. Run the composed audit before and after the change.
5. After a GitHub Pages deployment, verify the result at `https://www.infolog.io/`. A local server is not proof of publication and must not be shared as a public link.

Do not replace the production source with another preview or deploy through a new host unless the user explicitly requests that change.
